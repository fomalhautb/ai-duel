# Agent 卡牌对战游戏｜游戏机制与流程 V0.1

## 1. 游戏概念
这是一款以真实 AI Agent 为核心卡牌的双人策略对战游戏。玩家不直接回答问题，而是通过选择不同 AI 模型作为自己的 Agent，让真实 AI 处理系统给出的挑战题目。玩家需要同时管理自己的卡组、技能效果和有限 Token，在有限资源下选择最合适的 Agent 获得胜利。

游戏参考《炉石传说》等成熟数字卡牌游戏的核心结构，包括牌组构筑、英雄选择、卡牌费用、有限资源管理、先后手机制、回合制对战、技能卡与角色卡组合以及明确的胜负目标。但核心战斗不是传统的攻击与生命值，而是“技能干扰 + Agent 实际答题”的真实 AI 对决。

## 2. 核心胜利目标
双方玩家争夺积分。每轮产生一名获胜玩家：后手玩家获胜 +1 分，先手玩家获胜 +1.5 分，平局双方均不获得积分。任意玩家累计积分达到或超过 5 分，立即获得整局比赛胜利。

后手能够看到先手已经使用的技能牌后再进行应对，因此天然具有一定信息优势，所以先手获胜给予更高积分。每轮结束后双方先后手身份自动交换，例如第 1 轮 A 先手、B 后手，第 2 轮 B 先手、A 后手，第 3 轮再交换回来。

## 3. 牌组构筑
每名玩家在进入比赛前自行组建一套 20 张牌的牌组。进入比赛后，这 20 张牌构成玩家本局可以使用的卡牌资源。卡牌目前分为两大类型：Agent 牌和技能牌。

### 3.1 Agent 牌
Agent 牌代表真实 AI 模型，例如 GPT、Claude、Gemini、DeepSeek、Qwen 等。每张 Agent 牌至少包含 Agent 名称、模型名称、Token 消耗、基础信息、视觉形象以及可选能力标签。

Agent 牌并不是通过预设攻击力、生命值等数值直接战斗。玩家打出 Agent 后，后台会真实调用对应模型 API，让该模型回答当前挑战题目，再由系统根据真实回答判定结果。

### 3.2 技能牌
技能牌不会直接回答问题，而是影响当前回合的 Agent 对决。技能可以作用于对方 Agent 的输入、上下文、指令，也可以影响己方 Agent、Token、出牌条件、回答规则或当前回合环境。例如加入大量无关上下文、要求对方 Agent 必须按照某种形式回答等。具体技能牌内容后续单独设计，当前版本只保留完整技能机制。

技能牌的意义是让游戏从单纯“选择最强模型”转变为“技能组合 + Agent 选择 + Token 管理”的策略博弈。

## 4. 英雄系统
每名玩家进入比赛前需要选择一位英雄。英雄均以计算机科学、人工智能及相关技术领域具有代表性的女性人物为原型，并承担传统卡牌游戏中的英雄角色功能。

每位英雄拥有独立的专属技能，技能设计与该人物的研究领域、代表性成果、技术贡献或生平经历相关。英雄技能可以设计为主动技能、被动技能、每局限定技能、每若干轮可发动技能，或围绕 Token、Agent、技能牌等产生效果。具体英雄和技能暂不定义，但需要保留完整的英雄技能机制。英雄技能不占用 20 张牌的牌组空间。

## 5. Token 系统
Token 是游戏最核心的资源，作用类似《炉石传说》中的法力水晶，但更强调“整局比赛中的有限算力资源”。所有 Agent 牌和技能牌都有对应 Token Cost，只有当前剩余 Token 大于等于卡牌费用时才能打出，否则卡牌处于不可使用状态。

游戏内 Token 与后台 API 实际消耗的 Token 完全分离。例如游戏里 GPT Agent 可能消耗 8 Token，但后台真实 API 可能消耗数千个 Token。游戏 Token 只是经过抽象和平衡后的“算力价值”，不与真实 API Token 做 1:1 对应，这样可以避免不同模型计费规则和上下文长度影响游戏体验。

建议初始版本每名玩家拥有固定总 Token，例如 100 点，并且 Token 默认不会每轮完全恢复。具体数值后续根据试玩调整，但“整局资源有限”应作为核心机制保留。玩家需要不断判断：是否值得为这一轮投入更多 Token、是否要使用昂贵 Agent、是否应该保存资源到后面的关键题目。

## 6. 卡牌消耗规则
玩家初始拥有自己构筑的 20 张牌。卡牌使用后进入弃牌区，本局默认不能再次使用。因此打出 Agent 不只是消耗 Token，也意味着这张 Agent 牌已经消耗；技能牌同理。

玩家实际需要同时管理三种资源：牌组资源、Token 资源和积分。这可以避免玩家每轮重复使用同一个最强 Agent，也让牌组构筑和资源保留产生长期策略。

## 7. 单轮完整流程
每一轮依次经历：确定先后手 → 技能出牌 → 题目揭晓 → Agent 选择 → Agent 揭晓 → 真实 AI 答题 → 系统裁判 → 积分结算 → 回合清理 → 进入下一轮。

### 7.1 确定先后手
比赛第一轮开始时，系统随机决定双方先后手。后续每轮不再随机，而是双方身份直接交换。

### 7.2 技能出牌阶段
技能阶段开始时，题目尚未公开。先手玩家首先行动，可以不使用技能牌，也可以使用一张或多张技能牌，只要 Token 足够。操作完成后点击“结束出牌”。随后后手玩家进入技能阶段，后手能够看到先手已经打出的技能牌，再决定是否使用自己的技能进行应对，最后同样点击“结束出牌”。

技能牌原则上只影响当前回合，除非卡面明确写有持续效果。系统按照卡牌打出顺序建立技能效果队列，数值类效果可以叠加，相互冲突的指令按照卡牌规则决定优先级，所有效果由系统自动执行，并最终作用于 Agent 接收到的 Prompt、Context 或其他游戏状态。

### 7.3 挑战题目揭晓
双方都结束技能阶段后，系统正式展示本轮挑战题目，这是双方第一次看到完整题目。题目可以来自视觉识别、视觉计数、空间理解、语言陷阱、逻辑推理、常识判断、规则服从、信息不足判断、反直觉问题等类别。

核心选题原则是：对人类而言简单、直觉甚至有趣，但 AI 存在真实出错可能。每道题提前具有题目、分类、输入内容、标准答案和判定规则，以保证系统可以自动裁判。

### 7.4 Agent 选择
题目公布后，双方各选择一张自己仍然拥有且当前 Token 足够支付的 Agent 牌。双方选择必须隐藏进行，不能看到对方选择。双方分别点击“确认 Agent”，只有双方都确认后才同时公开，避免后选择者根据对方 Agent 临时做针对性选择。

### 7.5 Agent 揭晓与真实答题
双方 Agent 同时公开后，系统分别调用对应 AI 模型 API。系统会将“挑战题目 + 当前技能效果 + 系统 Prompt”组合成该 Agent 实际收到的输入。两个 Agent 独立生成答案，游戏界面可以表现为 Agent 部署、思考、回答生成和最终提交的过程。

### 7.6 系统裁判
系统自动比较两个 Agent 的答案，不需要真人裁判。题库优先使用具有明确标准答案的问题，例如数值题、选择题、识别题、规则执行题等，从而可以通过预设规则直接判定正确与错误。

## 8. 回合胜负判定
裁判采用分层判定机制。

第一优先级是答案正确性：一方正确、一方错误，则正确方直接获胜。

第二优先级是 Token 效率：如果双方都回答正确，则比较双方本轮实际消耗的游戏 Token。本轮 Token 消耗 = 本轮技能牌费用 + Agent 牌费用。消耗更少的一方获胜。例如玩家 A 使用 4 Token 技能 + 8 Token Agent，共消耗 12；玩家 B 使用 2 Token 技能 + 6 Token Agent，共消耗 8，如果双方都答对，则玩家 B 获胜。这一规则确保游戏核心不是“始终使用最强模型”，而是“用尽可能低的成本解决当前问题”。

第三优先级是平局：如果双方都回答正确且 Token 消耗完全相同，则本轮平局；如果双方全部回答错误，同样判定为平局。平局双方均不获得积分。

## 9. 积分结算
系统产生本轮赢家后，根据该玩家本轮的先后手身份计算积分：后手获胜 +1 分，先手获胜 +1.5 分。结算后立即检查是否有玩家累计达到 5 分，若达到则比赛结束。

## 10. 回合结束与下一轮
如果比赛尚未结束，系统依次更新双方积分、扣除本轮消耗 Token、将已使用 Agent 和技能牌移入弃牌区、清除仅持续本轮的技能效果、保存本轮战斗记录，然后双方先后手自动交换并进入下一轮。

下一轮流程完全一致：技能阶段 → 题目揭晓 → 双方秘密选择 Agent → Agent 真实回答 → 系统裁判 → 积分结算。持续循环直到某位玩家达到 5 分。

## 11. Token 耗尽与 Agent 不足
如果玩家已经没有足够 Token 使用任何 Agent，则无法正常参加当前挑战。如果对方可以正常派出 Agent 并正确完成问题，对方直接获得本轮胜利。如果玩家已经没有任何 Agent 牌，也视为无法正常参加挑战。

因此后续正式平衡时，需要增加牌组构筑限制，例如 20 张牌中至少包含一定数量的 Agent 牌。具体数量通过试玩确定。

## 12. 完整状态机
单轮状态固定为：`ROUND START → FIRST PLAYER SKILL → SECOND PLAYER SKILL → QUESTION REVEAL → AGENT SELECT → AGENT REVEAL → AI RUN → JUDGE → SCORE → CLEANUP → NEXT ROUND`。

对应中文流程为：显示轮次并确定先后手 → 先手使用技能 → 后手使用技能 → 展示题目 → 双方秘密选择 Agent → 同时翻开 Agent → 调用真实 AI API → 系统判断答案 → 根据胜负和先后手增加积分 → 卡牌进入弃牌区并清除效果 → 交换先后手进入下一轮。

## 13. 游戏策略来源
游戏的策略主要来自四层。第一层是牌组构筑：20 张牌中带多少强 Agent、便宜 Agent、技能牌以及如何组合。第二层是 Token 管理：是否值得为了当前回合投入大量 Token，何时使用昂贵 Agent，何时保存资源。第三层是技能博弈：先手需要在不知道后手如何应对的情况下下注，后手则可以看到先手技能后进行针对。第四层是 Agent 选择：题目揭晓后判断当前题目到底有多难，是否需要顶级模型，还是可以用便宜模型完成。

因此核心循环可以概括为：**先下注技能 → 揭晓挑战 → 选择 Agent → AI 真实对决 → 比较正确率与 Token 效率 → 获得积分。**

## 14. 与传统卡牌游戏的核心区别
传统卡牌游戏主要围绕攻击力、生命值和固定技能数值展开。本游戏的 Agent 卡没有固定“攻击力决定输赢”的机制，每一场战斗的真正结果来自现实中的 AI 模型真实运行结果。

同一张 GPT、Claude、Gemini 或 DeepSeek 卡，上一轮可能获胜，下一轮也可能因为题型、Prompt 干扰或技能效果而翻车。因此卡牌代表的不是一个预先写死的数值角色，而是一个真正运行中的 AI Agent。这也是整个项目最核心的产品特征。

## 15. 赛后战报
比赛结束后可以展示完整战报，包括获胜玩家、最终比分、总 Token 消耗、剩余 Token、使用过的 Agent、Agent 正确率、各轮胜负、最省 Token 的一轮、最具价值 Agent 以及技能使用记录。赛后战报既可以增强游戏反馈，也可以逐步沉淀真实模型表现数据。
